# PL-06 — Mobile polish

**Phase** 3 · **Size** M · **Depends on** SC-02, BN-03

## Goal
On a mid-range Android phone held in one hand, the whole thing is comfortable and smooth.

## Owns
Cross-cutting: `src/scene/*.module.css`, `src/binder/*.module.css`, `src/app/layout.module.css`, `src/chrome/Header.module.css` — **CSS only**, plus `docs/design/mobile.md`. Any TSX change is a Request to the owning lane or done here with a listed justification.

## Scope
- Thumb zones: hold targets (box, focused pack, reveal stack, stage card controls) sit in the lower 60 % of the viewport in portrait; header controls are reachable but never primary.
- Safe areas (`env(safe-area-inset-*)`), `100dvh`, address-bar resize without layout jumps; landscape phone fallback (binder becomes right rail at ≥ 640 px wide && ≤ 500 px tall).
- Performance: profile on a throttled CPU (4×) in Chromium: no frame > 32 ms during hold, tear, draw, collect. Fix by promoting layers (`will-change` on the moving element only during the move), avoiding box-shadow animation (animate a pseudo-element's transform instead), and using `transform`/`opacity` only.
- Tap highlight removal, `touch-action` per element, `-webkit-user-select: none` on interactive stage objects (never on text in detail).
- Text sizes: minimum 16 px for body; controls 44 px; detail text column line length 45–70 chars.

## Acceptance criteria
- [ ] Playwright mobile with CPU throttling (`client.send('Emulation.setCPUThrottlingRate', {rate: 4})` on chromium mobile emulation — add a `mobile-chromium` project here) — `tearPack()` + `drawCard()` + `collect()` produce no long tasks > 50 ms (`PerformanceObserver` in init script).
- [ ] No horizontal overflow at 360×640, 390×844, 412×915; landscape 844×390 usable.
- [ ] Pim plays it on his phone and notes in `docs/checkpoints/M3.md`.
