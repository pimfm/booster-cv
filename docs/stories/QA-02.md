# QA-02 — Visual review run

**Phase** 5 · **Size** S · **Depends on** QA-01 · **Executed by the reviewer agent, not a builder**

## Goal
One fresh pair of eyes walks the entire thing against the brief and the spec and writes down everything that is off.

## Owns
`docs/checkpoints/M5-review.md`, follow-up story stubs in `docs/stories/FX-*.md` (fixes).

## Protocol
1. Fresh clone, `npm run build && npm run preview`; open on desktop (1440 and 1280×720) and a real phone (via the deployed URL from PL-05).
2. Play through three times: as a hurried store owner (skip reading), as a curious one (read everything), keyboard-only.
3. For every screen and transition, answer DESIGN-BRIEF §2's five questions; note timing feel against INTERACTION-SPEC; note copy issues (tone, length, NL/EN parity).
4. Check link previews (OG) in at least WhatsApp Web and LinkedIn post composer (do not post).
5. Record findings as a table: severity (blocker / should / nice), location, spec reference, suggested fix; create `FX-nn` story files for blockers and shoulds (size S each, dependencies QA-02).

## Acceptance criteria
- [ ] `M5-review.md` complete with the table and three one-paragraph playthrough impressions.
- [ ] Every blocker has an FX story; Pim triages shoulds/nices in the file.
