# CT-02 — Dev card gallery

**Phase** 4 · **Size** M · **Depends on** CR-01, CR-03

## Goal
Pim writes with the result visible: every card, every size, both languages, errors inline. Spec: CONTENT-AUTHORING §4.

## Owns
`src/dev/cards/Gallery.tsx`, `Gallery.module.css`, `src/dev/cards/useContentValidation.ts`, `src/dev/cards/filters.ts`.

## Scope
- `/dev/cards`: per pack, each card as a row: EN stage card · NL stage card · slot size · a "Detail" button opening the real `CardDetail` (standalone, without the machine — pass `cardId` prop).
- Validation runs in the browser with the same zod schema + rules (share code with `content-check` via `src/content/rules.ts` — move the rules there in this story; `content-check.mjs` imports the built rules or duplicates minimal logic with a test asserting parity).
- Errors/warnings render as a red/amber border and a message under the card; a summary bar at the top: `24 cards · 3 errors · 2 warnings · 9 missing art`.
- Filters via query: `?pack=`, `?rarity=`, `?missing=art|nl|en`, `?q=` title search.
- Hot reload: editing a content file updates the gallery (Vite handles it; verify the eager glob doesn't block HMR — if it does, switch loader to lazy glob in dev).
- Excluded from production build.

## Acceptance criteria
- [ ] RTL: gallery renders all placeholder cards; an injected invalid card shows the correct message.
- [ ] Rules parity test between browser and script.
- [ ] HMR: editing a card's title updates the gallery in < 1 s (manual check noted in PR).
- [ ] Screenshot `CT-02-gallery-desktop-chromium.png`.
