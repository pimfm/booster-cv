# BN-01 — Binder

**Phase** 2 · **Lane** D · **Size** M · **Depends on** D-03

## Goal
The visitor always sees the shape of the whole CV and where each card went. Spec: INTERACTION-SPEC §9.

## Owns
`src/binder/Binder.tsx`, `Binder.module.css`, `src/binder/BinderGroup.tsx`, `src/binder/BinderSlot.tsx`, `BinderSlot.module.css`.

## Scope
- Desktop rail (220 px): header placeholder (BN-02 fills), then one `BinderGroup` per pack in content order: pack name label with tint swatch, a 3-column grid of `BinderSlot`s.
- `BinderSlot`: empty = dashed 2 px outline with card number; filled = `Card size="slot"` wrapped in a button → `OPEN_DETAIL { cardId }`. Filled slot carries `layoutId={layoutIds.card(id)}` **only during the collect flight and until the next draw**, then switches to a static render keyed differently — otherwise every slot competes for the same layoutId as the stage/detail card. Document this in a comment; test it.
- Landing: on fill, border 2 → 3 px (`dur.sm`) and a 2 px overshoot via `spring.card`. Emit `card:collected` event for audio.
- Current pack's group scrolls into view when a pack is focused (desktop rail `scrollIntoView({ block: 'nearest' })`).
- Mobile: BN-01 renders the bottom strip with **filled slots only**, horizontal scroll, newest at the right end and scrolled into view on collect; the sheet is BN-03.
- Binder is a `<nav aria-label=strings.binder>`; slots are buttons with `aria-label` "`title`, `rarity`, collected" or "slot `n`, empty".

## Acceptance criteria
- [ ] RTL: slots for every card in content order; filled vs empty from `collected`; click filled → `OPEN_DETAIL` with id; empty not focusable.
- [ ] Playwright: after `collect()`, the slot for that card is filled and (desktop) visible within the rail; (mobile) the strip is scrolled to it.
- [ ] `layoutId` uniqueness: at any time at most one mounted element per card id has that layoutId (test by querying `[data-layout-id]` in test mode).
- [ ] Screenshots `BN-01-rail-*.png` with 7 collected across 2 packs; reviewer approval.
