**Phase** 2 · **Lane** B · **Size** M · **Depends on** PK-02, BX-02 (reuses `useHold` and the audio/event bus)

## Goal
The signature interaction, on the pack. Spec: INTERACTION-SPEC §3.

## Owns
`src/scene/FocusedPack.tsx` (behaviour), `src/scene/PackTear.tsx`, `src/scene/PackMouth.tsx`.

## Scope
- Reuse `useHold` from lane A exactly (do not fork it; request changes if needed).
- Progress mapping (via `select.holdVisual`): seam highlight width, `skewX(-1.5deg·p)`, `scale(1 − 0.04p)`, content shift 2 px; marks at 0.33/0.66 (shake + `hold:mark` event).
- Tear: crimp strip detaches (`y −40, x 24, rotate 9°`, `spring.pack`, fade); body drops 8 px to opacity 0.75; emit `pack:tear` event.
- `PackMouth`: the opening from which the stack rises — the stack itself is lane C's `RevealStack`; coordinate via phase: at `pack-torn` the `RevealStack` mounts with its own enter animation positioned at `--mouth-x/--mouth-y` CSS vars that `FocusedPack` writes on the Stage element (document in `layoutIds.ts` comments: "mouth position contract"). After 400 ms the pack body fades; the machine moves to `revealing` when `RevealStack` reports `onSettled` → dispatch `STACK_READY`? **No new action**: `pack-torn → revealing` is a timed transition inside lane C's component using `DISMISS`-free approach: lane C dispatches `DRAW`-enabling by calling `dispatch({type:'TEAR_COMPLETE'})` only in reduced motion. Keep it simple: machine enters `revealing` immediately at tear; the *visual* stack-rise plays during `revealing` and `RevealStack` ignores `DRAW_CARD` clicks for its first 400 ms (`pointer-events: none` while entering). Record this clarification in INTERACTION-SPEC §3 in the PR.
- Reduced motion: strip fades out; no skew/scale.
