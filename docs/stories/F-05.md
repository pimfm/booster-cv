# F-05 — Test harness

**Phase** 0 · **Size** S · **Depends on** F-01, F-04

## Goal
Every later story can write a Playwright test for a hold, a draw, or a collect in three lines, on desktop and mobile, with and without reduced motion.

## Owns
`playwright.config.ts`, `e2e/fixtures.ts`, `e2e/helpers/*.ts`, `e2e/__screens__/.gitkeep`, `e2e/README.md`.

## Scope
- Projects: `desktop-chromium` (1440×900), `mobile-webkit` (iPhone 14 device descriptor), and `-reduced` variants of both using `contextOptions: { reducedMotion: 'reduce' }`.
- Fixture `app`: navigates to `/`, sets `window.__BOOSTER_HOLD_MS__ = 50` via `addInitScript`, clears localStorage, exposes `openBox()`, `focusPack(id)`, `tearPack()`, `drawCard()`, `openDetail()`, `closeDetail()`, `collect()`, `phase()` (reads `data-phase` on `<main>`), `binderCount()`.
- Hold helper uses `mouse.down()`/`touchscreen` appropriately per project, waits `holdMs + 80`, then `up()`. Keyboard variant `holdKey('Space')` uses `keyboard.down/up`.
- `shot(name)` helper writes `e2e/__screens__/<ID>-<name>-<project>.png` (full page, `animations: 'disabled'` off — we want real frames — but waits for `data-animating="false"` on `<main>` which the Provider sets when no Framer animations are running; implement via `useAnimationFrame` counter in F-06 if not trivial, else a 400 ms settle).
- `e2e/README.md`: how to write a story spec, naming, screenshot rule.

## Acceptance criteria
- [ ] `npm run e2e` runs 4 projects; a sample spec `e2e/F-05.spec.ts` asserts `phase()` moves `sealed → box-open` via `openBox()` on all 4 (uses the F-06 stub box which renders a hold target).
- [ ] Reduced-motion projects complete the same spec in < 2 s each.
- [ ] CI uploads `e2e/__screens__` and Playwright traces on failure as artifacts.

## Out of scope
Journey suites (QA-01).
