# CT-01 — Content scaffolder

**Phase** 4 · **Size** S · **Depends on** F-03

## Goal
Pim adds a card in one command and never hand-edits `packs.ts` for ordering by accident.

## Owns
`scripts/content-new.mjs`, `content/cards/_template.ts`, `content/.ids.lock`, the `--write-lock` flow in `scripts/content-check.mjs`, `docs/CONTENT-AUTHORING.md` §3 (keep in sync).

## Scope
- `npm run content:new -- --id <kebab> --pack <packId> [--rarity common] [--kind trait] [--after <cardId>]`: validates id (kebab, unique), copies the template with id/kind/rarity filled, appends to the pack's `cards` (or inserts after `--after`), prints the file path and a reminder to run `/dev/cards`.
- `npm run content:check -- --write-lock` rewrites `.ids.lock`; plain check compares and explains: "card `x` removed/renamed since lock; bump `meta.contentVersion` (currently 1) or restore the id".
- `npm run content:stats`: prints cards per pack, rarity distribution vs the CONTENT-WORKSHOP §3 targets, missing art/locale counts. (Tiny; helps Pim finish.)

## Acceptance criteria
- [ ] Vitest with a temp copy of `content/`: creating, duplicate id error, `--after` ordering, lock mismatch message.
- [ ] Running `content:new` twice with the same id fails without touching files.
- [ ] CONTENT-AUTHORING.md commands match the implementation (doc test: grep the flags).
