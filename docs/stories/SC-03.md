# SC-03 — Tuning session

**Phase** 2 · **Size** S · **Depends on** SC-02 · **Requires Pim present**

## Goal
Numbers chosen by reading a spec are rarely right the first time. Tune with the human, change only numbers.

## Owns
`src/design/motion.ts`, the numeric values in `docs/INTERACTION-SPEC.md`, `src/dev/tuning/Tuning.tsx` (dev route `/dev/tuning`).

## Scope
- Build `/dev/tuning`: live sliders for every value in `motion.ts` (dur, spring stiffness/damping/mass, hold duration, cancel return, overshoot) writing to a `window.__MOTION_OVERRIDES__` that `motion.ts` reads in dev; an "Export" button prints the resulting `motion.ts` body. The experience runs in the same page (embed `<App/>` in an iframe at phone and desktop widths side by side).
- Session protocol with Pim (write results to `docs/checkpoints/M2-tuning.md`): for each of box hold, box open, pack focus, pack tear, draw, rare beat, collect flight, detail open, pack-complete, reset — Pim rates 1–5 on *weight*, *anticipation*, *settle*, *speed*; adjust; record final values.
- Apply final values to `motion.ts` and the spec; attach before/after videos.

## Acceptance criteria
- [ ] PR diff touches only the owned files (+ screenshots/videos).
- [ ] Spec numbers and `motion.ts` agree (a Vitest test parses the spec's code block in DESIGN-BRIEF §3 and compares to `motion.ts` — add it here).
- [ ] All existing e2e still pass (hold override unaffected).
